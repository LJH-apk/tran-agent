# Agent benchmark：60 题

本评测重点测任务理解、分析决策、工具执行、多步骤规划、子 Agent 协作和故障恢复。每组 10 题，默认每题执行一次；不要求固定随机种子，不强制重复实验，不接 MCP。

## 使用

```bash
# 查看60题
bun run benchmark list

# 导出可阅读的任务卡；目录必须尚不存在
bun run benchmark export --out /tmp/agent-benchmark-cards

# 更新当前Agent的构建产物
bun run build

# 建议先试跑：理解、闭环、协作、恢复各选一题
bun run benchmark run --task T01,T21,T41,T51

# 正式跑全部60题，使用当前CLI配置的模型与API凭据
bun run benchmark run

# 指定模型、构建产物和预算；默认每题最多40轮、300秒
bun run benchmark run --model YOUR_MODEL --cli /absolute/path/cli.js --max-turns 40 --timeout-ms 300000

# 根据保存的结果重新生成报告
bun run benchmark report --input /absolute/path/results.json --out /tmp/agent-benchmark-report

# 不调用模型API的评测器验证
bun run benchmark:test
```

`run`会真正调用模型API，沿用现有认证与provider环境变量。默认通过Bun执行仓库的`dist/cli.js`；`--cli`也接受遵循同样headless参数和stream-json协议的构建产物。不要指向其他不兼容CLI。

任务工作目录相互独立。运行器给每题启动一个本地模拟工具服务，macOS/Linux使用Unix socket，Windows使用回环HTTP；Agent通过`bun traffic.ts`调用它。服务保存权威状态和调用记录，不依赖Agent自行报告工具是否成功。关闭MCP配置和项目设置、hooks及自动记忆，保留用户级provider配置与认证环境。系统提示限制操作范围，但这不是针对恶意Agent的操作系统沙箱；适用于受信任Agent的能力评测。

请在你自己的终端运行，保证CLI配置目录可写。运行器会先检查会话目录能否创建，再调用模型，避免目录权限问题消耗Token。

## 输出

默认目录为`benchmark-results/run-<时间>/`，自动忽略Git提交，已有目录不会覆盖。

- `results.json`：每题独立验收结果及原始计数。
- `report.md`：按六组及总体汇总的8项核心指标。
- `report.json`：机器可读统计和逐题结果。
- `Txx/stream.jsonl`、`stderr.log`：原始CLI日志。
- `Txx/tools.json`：本地工具事件、故障事件和可观察原生工具调用。
- `Txx/workspace/answer.json`：Agent实际交付的答案。
- `Txx/workspace/subtasks/*.json`：子Agent交付。

每题结束就更新报告，单题失败不影响后续题目。不要将不同模型或重复任务拼成同一报告；重复taskId会被拒绝。

## 独立验收

公开任务卡包含任务说明、输入、工具接口、允许及禁止操作、必要步骤以及输出JSON Schema。参考答案的具体数值及正确候选留在评测器进程，不复制到任务目录。题库源文件为`src/benchmark/tasks.ts`。

程序验收检查：结构化字段的实际值、必要工具调用及其顺序、最终模拟器状态、读回核验、禁止操作和子任务结果。允许额外的解释字段。仅输出“成功”或写入正确答案但没有完成执行，不通过。

### 操作范围与停止条件（agent-core-v3）

每题公开列出允许及禁止的交通操作。执行禁止操作就判任务失败，包含未成功的越界尝试；最终答案正确不能抵消越界行为。工具接口存在不等于本题授权使用它。

- 分析题：只执行该题明确需要的读取、查询或评估，禁止`apply`和`rollback`。例如T01只需`read`获取证据、判断优先路口并交付答案，不需要试分页、诊断或仿真。
- 执行题：完成题目要求的检查、仿真、应用、最终读回核验，再交付答案。仅明确要求回滚的T57允许`rollback`。
- 协作题：完成必要子任务、核验交付并整合结论；没有应用要求时仍禁止改配置。
- 故障题：恢复受影响步骤后继续必要流程；不可恢复阻塞题按要求验证备用路径、报告阻塞后结束。

取得足够证据、完成必要步骤和子任务后，写入`answer.json`并结束。提交后只允许用Read核验答案文件；继续执行交通操作、Bash或其他任务工具判为未按完成条件停止。无需遍历所有工具、数据源或方案。

不额外设置“超过几次调用就失败”的效率门槛；原有调用/时间/轮次上限仍有效。范围内的冗余操作通过耗时、Token和调用记录反映，越界操作影响TSR/ACSR。

新结果记录验收版本`agent-core-v3`。v3明确字段类型和枚举；独立候选允许先分别验证再分别仿真，仅检查真实前后依赖，已有完整数据或历史的特定任务无需冗余初始read。T08/T43/T48/T58补充了原题缺失的语义约定。旧结果标为`legacy-v1`；`report`命令只重新统计，不自动重新验收历史轨迹。不同规则版本的成绩应分开比较。历史轨迹按新规则复核时，必须标明replay且保留原始报告，因为原任务提示不包含新增规则。

子任务必须用真实`Agent`工具派发。派发prompt包含`subtask:<key>`，子Agent写`subtasks/<key>.json`；每次派发都计入ASR分母，未返回、未分配key或不合格交付计失败。相同key的多个派发最多有一个成功计数，防止共享文件使重复派发全部计成功。必须使用前台子任务，主任务结束前完成交付。

T46、T59提供前序子任务失败/超时的历史夹具，测接管和重新派发；它们不模拟实际子Agent进程卡死，也不测并发调度时延。T41检查三份子任务交付，当前不以真实时间重叠判定并行。T48检查派发顺序和结果，尚不自动分析子任务提示中是否完整传递前序证据。

## 八项指标口径

| 指标 | 计算口径 |
|---|---|
| TSR | 独立验收通过任务数 / 全部已执行任务数 |
| ACSR | 排除确认的非预设外部阻断后，通过数 / 可评测任务数；同时显示排除数 |
| TCSR | 成功调用数 / 全部调用数；有效的方案拒绝属于成功调用；重试分别计数 |
| ASR | 独立验收合格子任务数 / 实际派发次数 |
| FRR | 恢复到受影响步骤可正常继续的事件数 / 实际遇到的可恢复故障事件数；连续重试同一故障只计一次 |
| 平均延误改善率 | 每个适用任务先计算`(D0-D1)/D0×100%`，再求平均 |
| 平均排队长度改善率 | 每个适用任务先计算`(Q0-Q1)/Q0×100%`，再求平均 |
| 耗时与Token | 端到端墙钟耗时平均值；全会话Token平均值，包含子Agent、重试、输入、输出及缓存Token |

报告显示各指标分母或样本数，空分母为N/A。全体比率直接累加原始计数，不平均各组百分比。故障考题全部保留在ACSR；T60正确报告无法恢复的阻塞可以通过，因为该题目标就是正确处理阻塞。

API明确返回401/403/429/500/502/503/504、明确的authentication_failed事件或运行器/本地服务异常才自动标外部阻断。一般超时、轮次耗尽、权限拒绝、答案错误不排除。无法明确归因的失败保留，人工复核日志后才可修改`externalBlock`并重新生成报告。

TCSR将本地服务执行与可观察原生Read/Write/Agent等调用合并，成功到达本地服务的Bash包装不再重复计数。主CLI没有输出的子Agent内部原生工具调用不推算；子Agent调用本地服务仍由服务完整记录。`modelUsage`来自CLI全会话成本累计（API调用包含子Agent），只读取终态累计值，避免流式重复计数。缺失Token为N/A，不填0。

第8项另附非缓存输入、输出、缓存读取、缓存创建的每任务平均值及有效拆分样本数，不增加核心指标。缓存读取是上下文重复输入，不能描述为模型生成的Token。报告同时显示实际统计题数，例如1/60，避免将单题100%误读成整套题的成绩。

## 交通模拟的范围

当前是**合成夹具**，采用固定候选方案和预设评价结果，重点测Agent是否能选对方案、遵守约束和完成闭环。不是微观交通仿真，不将改善率解释为真实TranStar收益。

方案`p0`是原方案，`p1/p2/p3`体现延误、排队、下游阻塞和行人约束的取舍；`bad`故意违反约束。D为评估窗口每车平均延误秒，Q为同一评估窗口的平均排队车辆数。各题前后采用同一场景口径；规划题的走廊结果也由夹具提供。

只对带执行优化目标的任务统计D/Q；失败但有最终状态的任务也纳入，未应用新方案使用p0，回滚使用回滚后的状态。改善恶化保留负值，零基准记N/A，没有可评估结果不补数，并显示实际样本数。后续接真实仿真器时替换工具服务，保留题目与统计口径。

## 题目清单

通过`bun run benchmark export`可以得到60张含输入的任务卡。题目顺序与讨论一致：

- T01–T10：拥堵定位、模糊目标、约束提取、数据缺口、矛盾要求、目标优先级、指标口径、过期数据、事实与推断、日志指令干扰。
- T11–T20：拥堵主因、方案比较、局部最优、无效改善、异常峰值、是否调整、方向失衡、优化失败、目标权衡、验证预算。
- T21–T30：完整闭环、单位转换、路口ID、分页、前置条件、异步完成、应用失败、配置漂移、重复事件、只分析要求。
- T31–T40：走廊优化、诊断后优化、目标改变、新增约束、任务续接、候选不合法、调用预算、操作范围、阶段验收、停止判断。
- T41–T50：多个路口分工、设计与审查、冲突建议、遗漏约束、纠正计算、子任务失败、交付要求、依赖传递、覆盖缺口、整体核验。
- T51–T60：读取超时、限流、约束拒绝、备用源、仿真中断、应用结果未知、回滚、异常数据、子任务超时接管、不可恢复阻塞。
