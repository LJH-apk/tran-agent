# 自适应信号控制谱系：从协调配时到 Max-Pressure

## 1. 四类思路

### 1.1 预定时段方案
通过历史需求设计周期、绿信比与相位差。优点是稳定、易解释；缺点是对日内随机波动和事件适应弱。

### 1.2 交通响应式协调
SCOOT/SCATS 等代表“连续监测 + 周期/绿信比/相位差调节”的系统工程思路。治理重点包括检测器布局、通信、容错和人工策略，而非只看算法名称。

### 1.3 预测优化 / MPC
OPAC、RHODES、滚动时域 QP 等通过短时预测搜索控制动作。优点是可显式放约束；风险来自预测误差和计算截止时间。

### 1.4 压力/队列反馈
TUC、Max-Pressure 直接利用队列/占有率状态。它们在过饱和网络中提供极强基线，因为核心目标是避免队列失衡与下游阻塞。

## 2. 为什么局部最优会失败

单路口减少平均延误可能增加下游排队并触发 spillback。协调评价至少需要：上游队列、下游可用存储、走廊旅行时间、网络吞吐和相邻路口阻塞时间。

## 3. 选择逻辑

- 稳定可预测需求：优化固定协调方案可能足够。
- 明显日内波动：交通响应式控制。
- 事件/强随机性 + 可预测短时状态：MPC/RHODES 类。
- 过饱和 + 队列可观测：TUC/Max-Pressure 类优先作为基线。
- 强多模式需求：在目标中加入公交/行人/自行车约束或 person-delay。

## 4. 关键约束

相位安全、最小绿、黄灯/全红、行人清空时间、最大周期、最大排队、下游存储、公交优先上限、队列估计误差。

## 5. 评价原则

不要用不同观测信息比较算法。例如 RL 使用全网精确队列而传统控制只用单线圈，占了信息优势。公平对比必须统一传感器可见状态、控制周期和安全约束。

## 6. Agent 输出模板

诊断：网络处于【欠饱和/近饱和/过饱和】；主要风险为【局部延误/排队回溢/走廊失协调】。
候选控制：A 固定协调；B 交通响应；C 队列反馈；D 预测优化。
选择理由：依据可观测状态、算力、需求波动、可解释性和部署复杂度。
基线：Webster/现状方案 + Max-Pressure/TUC 或成熟自适应控制。
