# 论文证据读取协议（给 Claude Code / Agent）

## 1. 每篇论文提取 12 个字段

1. 问题；2. 尺度；3. 网络类型；4. 交通状态；5. 决策变量；6. 数据来源；7. 基线；8. KPI；9. 主要发现；10. 适用条件；11. 局限；12. 可转化治理规则。

## 2. 证据等级

- **E1 真实世界长期/准实验**：拥堵收费、现场控制前后对比等。
- **E2 现场短期实验/真实数据校准**：合流控制、公交优先、实地检测器数据。
- **E3 多场景高质量仿真**：经校准、多个需求水平、多个随机种子。
- **E4 单一仿真/理想网络**：作为机制或算法证据，不作为直接实施证据。
- **E5 理论证明**：证明稳定性/最优性，但部署条件必须另行验证。

不同等级不是简单高低：理论可以非常强，但回答“现实可实施性”时不能代替现场证据。

## 3. 顶刊与高引的正确用法

高引用说明论文对领域影响大，不代表结论适用于所有场景。顶刊说明同行评审质量与研究重要性通常较高，也不消除外部有效性限制。Agent 使用“seminal/highly influential”即可，除非有可靠实时计量来源，否则不要写精确引用数。

## 4. 冲突证据

如果论文结论冲突：
- 对齐交通状态；
- 对齐基线；
- 对齐目标函数；
- 对齐传感器信息；
- 对齐网络尺度；
- 检查是否一个研究欠饱和、另一个过饱和。

先解释差异来源，不要简单投票。

## 5. ITSAC 文献落地句式

“依据 [文献类别]，该方法主要针对 [机理]。本场景的 [数据证据] 与其适用条件一致/部分一致，因此将其作为 [主方案/候选/基线]；同时通过 [敏感性/反事实仿真] 检查 [主要风险]。”
