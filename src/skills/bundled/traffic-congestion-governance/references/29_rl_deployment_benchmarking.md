# 强化学习交通控制：治理级证据与部署门槛

## 1. RL 的位置

RL 是控制器候选，不是治理目标。治理目标仍然是减少人均/车辆延误、提高可靠性、避免回溢、保障公交/行人并控制公平和安全风险。

## 2. 必须击败的基线

至少包含：
1. 现状配时；
2. Webster/协调固定时制；
3. SOTL 或成熟感应控制（如适用）；
4. Max-Pressure / TUC 类强控制基线；
5. 若声称网络协同，加入成熟网络协调方法。

只与“固定 30 秒绿灯”比较不足以证明价值。

## 3. 公平实验协议

- 相同路网；
- 相同 OD/随机种子集合；
- 相同观测信息；
- 相同相位安全约束；
- 相同 warm-up；
- 至少多种 demand level；
- 至少一个分布外 demand；
- 报告均值和方差/置信区间；
- 报告训练与推理成本；
- 明确是否使用未来信息。

## 4. Sim-to-real 风险

交通仿真的跟驰、换道、黄灯行为、队列估计误差、公交停站、行人、事故和检测器噪声都会形成 domain gap。治理级方案需要参数扰动、传感器噪声和行为模型敏感性测试。

## 5. 安全外壳

真实部署时 RL 动作应经过 rule-based safety shield：最小绿、黄灯、全红、行人清空、最大相位等待、最大周期以及紧急车辆约束。不要让神经网络直接绕过信号安全规则。

## 6. 可解释性

至少输出：状态 → 选择的相位 → 关键压力/需求证据 → 预计影响。若模型无法解释单步行为，运营人员很难在异常情况下接管。

## 7. Agent 红线

- 不得因训练回报更高就称“优于传统方法”。
- 不得只报平均延误而隐藏极端排队。
- 不得用不同传感器信息量做不公平对比。
- 不得把单一 4x4 网格结果外推到真实城市。
- 不得忽略训练随机性、种子和超参敏感性。
