# 拥堵定价：从经济学原理到可实施治理

## 1. 核心原则

拥堵收费的目标不是“收费本身”，而是让高峰道路使用者面对其造成的边际拥堵成本，并通过出发时间、路线、方式、目的地或是否出行的调整减少最昂贵的峰值需求。治理 Agent 不得把“收费后流量下降”直接等同于成功；成功需要同时检查效率、可靠性、可达性、公平性、收入用途和公众接受度。

## 2. 设计维度

### 2.1 空间
- 点收费适用于桥隧、瓶颈或设施入口。
-  cordon 适用于中心区边界管理。
-  area license / 区域收费适用于进入或在区内行驶的管理。
-  distance-based 适用于更细粒度的道路使用费，但数据和隐私治理更复杂。

### 2.2 时间
- 固定高峰费简单但在临界时刻容易产生时间迁移和“肩峰”。
- 分时收费应与拥堵形成/消散过程一致，而不是机械按行政时段设置。
- 动态收费能够逼近实时边际成本，但稳定性、可解释性和接受度更难。

### 2.3 收入用途
将收入用于公交、步行骑行、低收入补贴或道路维护，会改变政策公平性与政治接受度。不要只报告“收入”，要区分转移支付与真实社会成本。

## 3. 实证证据如何使用

Stockholm 与 London 的价值在于提供全尺度实施证据。Agent 应从中抽取“设计—实施—观察—调整”机制，而不是复制费率。需要记录：收费边界、收费时段、豁免、替代交通、执法技术、交通变化、旅行时间、公众态度、运营成本和长期适应。

## 4. ITSAC/仿真建议

若赛题无法真实建模支付行为，可设置需求弹性场景：
1. 无行为变化：仅改变路线成本；
2. 低弹性：少量需求转移；
3. 中弹性：路线+时段+方式变化；
4. 高弹性压力测试。

至少比较总旅行时间、95%旅行时间、车辆公里、进入收费区流量、边界绕行、公交客流代理量和不同用户组广义成本。

## 5. 常见失败

- 只降低收费区内部流量，却把拥堵推到边界道路。
- 只报告平均速度，不报告出行完成量和可达性。
- 把收费收入当作社会福利净增加。
- 忽略低收入群体、必须驾车群体和残障出行。
- 没有替代方式却直接复制高收费方案。

## 6. Agent 决策规则

IF 需求长期超过供给 AND 高峰具有明显时间集中 THEN 把价格/时段管理列入候选。
IF 收费区边界存在低容量替代道路 THEN 强制评估绕行与社区外部性。
IF 公交/轨道有剩余承载能力 THEN 需求转移的可实施性更高。
IF 需要做公平评价 THEN 输出“谁支付、谁受益、收入如何回流、可达性如何变化”四列矩阵。
