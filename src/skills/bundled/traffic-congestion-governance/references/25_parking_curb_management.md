# 停车与路缘治理：把“找车位”纳入拥堵机理

## 1. 为什么停车是交通治理问题

CBD、医院、学校、商圈和枢纽周边的拥堵可能不是纯粹的通过交通，而是由低价路内停车、上下客、网约车等待、装卸、违停和反复巡游共同造成。此类问题若只加绿灯或扩车道，经常效果很差。

## 2. 诊断链

需求 → 到达路缘 → 可用车位/泊位 → 搜寻时间 → 低速巡游 → 换道/停车动作 → 有效车道数下降 → 饱和流率下降 → 排队增长。

必须区分：
- 停车供给不足；
- 停车价格太低导致长期高占用；
- 周转率低；
- 上下客泊位不足；
- 货运装卸与客运冲突；
- 路内停车挤占关键瓶颈；
- 信息不对称导致无谓搜索。

## 3. 治理工具箱

### 3.1 价格
目标不是“越贵越好”，而是保持一定可用泊位、减少巡游和提高周转。动态价格应设置变化上限与调整周期，避免用户预期过度波动。

### 3.2 空间再分配
在交叉口上游、公交站、学校门口等关键区段，取消少量路内停车可能比普遍拓宽道路更有效。要用“释放的有效通行能力/损失的停车服务”进行权衡。

### 3.3 路缘分时复用
同一空间可按时段配置为装卸、网约车上下客、短停、公交、步行扩展或普通停车。Agent 应把路缘当作动态资源而不是静态停车位。

### 3.4 信息与预约
预约装卸、停车诱导和可用泊位信息可减少搜索，但如果停车价格仍严重失真，信息系统只能部分缓解。

## 4. KPI

- 路内泊位占用率；
- 平均搜索时间；
- 路段巡游车辆比例；
- 换道次数/冲突代理指标；
- 路缘停靠持续时间；
- 关键车道有效占用；
- 公交站阻塞时间；
- 路段吞吐；
- 商业装卸完成率。

## 5. 仿真实现

如果微观仿真无法真实表现“找车位”，不要假装已经建模。可构建代理模型：将搜索车辆设置为低速循环路线并随机触发停车；用多个占用率场景测试敏感性。

## 6. Agent 规则

IF 商圈低速 + 频繁靠边停车/换道 + 高路缘占用 THEN 优先检查 curb/parking，而不是先改信号。
IF 交叉口出口附近违停导致有效车道减少 THEN 将清障/禁停列为低成本优先策略。
IF 停车治理减少巡游但增加远端步行 THEN 在可达性评价中记录这一转移。
