# Max-Pressure 与学习型控制

## Max-Pressure 核心
为每个可服务交通流定义“压力”，通常体现上游排队与下游排队/容量差。选择能够释放最大网络压力的相位组合。

### 治理含义
- 不能只看进口排队。
- 下游越堵，继续放行的价值越低。
- 网络稳定性优先于单点最优。

## 与 RL 的关系
PressLight 等工作显示，可以把交通理论直接编码进奖励和状态，而不是让 Agent 从零猜测“什么是好控制”。

## 学习型控制使用门槛
1. 强基线：Max-Pressure/TUC/SCOOT 类。
2. 泛化：未见需求、未见随机种子、未见事件。
3. 安全：最小绿、黄灯、全红、行人清空、队列储存约束。
4. 可解释：为什么切相位？哪个压力/队列触发？
5. 故障：检测器掉线、通讯中断时退回何种方案？
6. 计算：实时推理时延是否满足周期要求？

## 不要做的事
- 只与固定配时比较就宣称 RL 最优。
- 用训练场景测试场景同分布结果证明“泛化”。
- 奖励只用平均速度，忽略排队和下游阻塞。
- 不报告动作约束与黄灯逻辑。
